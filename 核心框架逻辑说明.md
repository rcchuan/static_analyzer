## 1. 总体架构

分析器采用经典**编译器 Pass 管道**架构，每个分析阶段顺序执行并将结果传递给下一阶段：

\`\`\`
源代码 (C/C++/Java/Python)
     │
     ▼
┌─────────────────────────────────────────────────────┐
│  Phase 1: 语言感知解析器  →  统一 IR (中间表示)     │
│  PythonParser (ast模块) / GenericParser (正则)      │
└──────────────────────┬──────────────────────────────┘
                       │ IRNode 树
                       ▼
┌─────────────────────────────────────────────────────┐
│  Phase 2: CFG 构建器  →  基本块 + 控制流边          │
│  BasicBlock 划分 + 后继/前驱关系建立                │
└──────────────────────┬──────────────────────────────┘
                       │ CFG (List[BasicBlock], List[CFGEdge])
                       ▼
┌─────────────────────────────────────────────────────┐
│  Phase 3: 数据流分析引擎                            │
│  • Reaching Definitions (可到达定义)                │
│  • Liveness Analysis (活性分析)                     │
│  → 检测未初始化变量、死赋值、不可达代码             │
└──────────────────────┬──────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────┐
│  Phase 4: 污点分析引擎                              │
│  Source → Propagation → Sink                        │
│  → 检测注入类漏洞、缓冲区溢出、资源泄漏            │
└──────────────────────┬──────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────┐
│  Phase 5: 模式检测器                                │
│  语言特定的正则/AST模式匹配                         │
│  → 代码坏味道、安全反模式、CWE漏洞                 │
└──────────────────────┬──────────────────────────────┘
                       │ AnalysisResult (含所有 AnalysisIssue)
                       ▼
┌─────────────────────────────────────────────────────┐
│  Phase 6: 修复报告生成器 + GUI 渲染                 │
│  按类别聚合问题 + CWE 链接 + 修复建议               │
└─────────────────────────────────────────────────────┘

```
	代码坏味道意味着：代码的设计或编写方式存在问题。虽然代码现在能跑通，但它的结构很糟糕，会导致未来维护困难、容易产生潜在 Bug、或者难以扩展。
例如：
过长函数 (Long Method)：一个函数写了几百行。这意味着逻辑太复杂，应该拆分。

重复代码 (Duplicate Code)：同样的代码在多处出现。一旦要修改，必须改动所有地方，极易漏掉。

过大类 (Large Class)：一个类承担了太多的职责（违反了单一职责原则）。

依恋情节 (Feature Envy)：一个函数频繁调用另一个类的属性或方法，远超过对自身类调用的频率。这暗示该函数可能放错位置了。

魔术数字 (Magic Numbers)：代码中直接出现硬编码的数字（如 if (status == 5)），而没有定义为常量。别人很难理解 5 代表什么。

过长参数列 (Long Parameter List)：一个函数传入了 7、8 个参数。
```



## 2. 中间表示层 (IR) — `core/ir.py`

设计思想

为了实现**跨语言分析**，设计了一套与语言无关的统一 IR，将 C/C++/Java/Python 的 AST 节点映射到相同的 `IRNode` 类型集合。

### 核心数据结构

```python
@dataclass
class IRNode:
    node_type: NodeType      # 统一节点类型枚举（IF/WHILE/CALL/ASSIGN等40+种）
    value: Optional[str]     # 节点携带的值（变量名/函数名/字面量）
    line: int                # 源码行号（用于问题定位）
    children: List[IRNode]   # 子节点（构成 AST 树）
    taint: bool              # 污点标记（是否携带不可信数据）
    taint_sources: Set[str]  # 污点来源集合
    reaching_defs: Set[str]  # 可到达定义集合（数据流注解）
```

**NodeType 枚举** 覆盖了四种语言的公共控制流结构：

| 类别 | 节点类型 |
|------|---------|
| 控制流 | IF, ELSE, WHILE, FOR, FOREACH, RETURN, BREAK, TRY, CATCH |
| 声明 | VAR_DECL, PARAM_DECL, FUNCTION, CLASS_DECL |
| 表达式 | ASSIGN, CALL, BINARY_OP, UNARY_OP, MEMBER_ACCESS |
| 字面量 | IDENTIFIER, LITERAL, STRING_LITERAL, NULL |

### 基本块定义

```python
@dataclass
class BasicBlock:
    id: int
    instructions: List[IRNode]    # 该块内的线性指令序列
    successors: List[BasicBlock]  # 后继块（CFG 出边目标）
    predecessors: List[BasicBlock]# 前驱块（CFG 入边来源）
    # 数据流集合（由分析算法填充）
    gen: Set[str]       # 该块新定义的变量
    kill: Set[str]      # 该块杀死（重定义）的变量
    in_set: Set[str]    # 入口处的可到达定义
    out_set: Set[str]   # 出口处的可到达定义
    live_in: Set[str]   # 入口处的活跃变量
    live_out: Set[str]  # 出口处的活跃变量
```

## 3. 解析层 — `parsers/`

### Python 解析器（高精度）

利用 Python 标准库 `ast` 模块，直接获取精确的 AST：

```python
class PythonParser:
    def parse(self, code: str) -> AnalysisResult:
        try:
            tree = ast.parse(code)          # 标准库 AST
            ir_root = self._convert_node(tree)
        except SyntaxError as e:
            # 捕获语法错误并记录为 AnalysisIssue
            ...

    def _ast_to_ir(self, node: ast.AST) -> IRNode:
        if isinstance(node, ast.FunctionDef):
            return IRNode(NodeType.FUNCTION, value=node.name, line=node.lineno)
        elif isinstance(node, ast.Assign):
            targets = ast.unparse(node.targets)    # 提取赋值目标
            return IRNode(NodeType.ASSIGN, value=targets, line=node.lineno)
        elif isinstance(node, ast.Call):
            func = ast.unparse(node.func)          # 提取被调函数名
            return IRNode(NodeType.CALL, value=func, line=node.lineno)
        ...
```

**关键设计**：Python 解析器用 `ast.unparse()` 将子树还原为字符串，保留了足够的语义信息，同时保持 IR 层的简洁性。

### 通用解析器（正则驱动）

对 C/C++/Java 使用正则表达式进行模式匹配，无需外部依赖：

```python
class GenericParser:
    def _parse_line(self, line: str, lineno: int) -> IRNode:
        # 函数声明模式
        if re.search(r'\b\w[\w\s\*]*\s+\w+\s*\([^)]*\)\s*\{?', line):
            m = re.search(r'(\w+)\s*\(', line)
            return IRNode(NodeType.FUNCTION, value=m.group(1), line=lineno)
        # 变量声明
        if re.match(r'(int|long|float|double|String|auto)\s+', line):
            return IRNode(NodeType.VAR_DECL, ...)
        # 赋值语句
        if '=' in line and not line.startswith('if'):
            return IRNode(NodeType.ASSIGN, ...)
        ...

    def _check_braces(self, code: str, result: AnalysisResult):
        """括号匹配检测：O(n) 栈式扫描"""
        depth = 0
        for i, ch in enumerate(code):
            if ch == '{': depth += 1
            elif ch == '}': depth -= 1
            if depth < 0:
                # 多余的 '}'
                line = code[:i].count('\n') + 1
                result.add_issue(AnalysisIssue(..., cwe_id="CWE-691"))
                depth = 0
```

## 4. 控制流图构建 — `analysis/cfg_builder.py`

### 基本块划分算法

基本块的边界由**控制流转移语句**决定：

```python
class CFGBuilder:
    def _process_node(self, node: IRNode, current: BasicBlock, ...) -> BasicBlock:
        if node.node_type == NodeType.IF:
            # 创建三个新块：true分支、false分支、合并点
            true_block  = self._new_block("if_true")
            false_block = self._new_block("if_false")
            merge_block = self._new_block("if_merge")
            
            self._add_edge(current, true_block,  "true")
            self._add_edge(current, false_block, "false")
            # ... 递归处理子节点
            self._add_edge(true_end,  merge_block, "")
            self._add_edge(false_end, merge_block, "")
            return merge_block

        elif node.node_type in (NodeType.WHILE, NodeType.FOR):
            loop_header = self._new_block("loop_header")
            loop_body   = self._new_block("loop_body")
            loop_exit   = self._new_block("loop_exit")
            
            self._add_edge(loop_header, loop_body, "true")
            self._add_edge(loop_header, loop_exit, "false")
            # 回边：循环体结束 → 循环头（构成环）
            self._add_edge(body_end, loop_header, "back")
            return loop_exit

        elif node.node_type == NodeType.RETURN:
            current.instructions.append(node)
            self._add_edge(current, exit_block, "")
            # return 之后的代码属于死代码块
            dead = self._new_block("dead_code")
            return dead
        else:
            # 普通语句：直接加入当前块
            current.instructions.append(node)
            return current
```

**回边识别**：循环体末尾到循环头的边标记为 `"back"`，是检测循环和识别 SCC（强连通分量）的关键。

## 5. 数据流分析引擎 — `analysis/dataflow.py`

### 可到达定义分析（前向数据流）

算法：经典**工作表迭代算法**（Worklist Algorithm）

```
// 初始化
for each BB:
    in[BB]  = ∅
    out[BB] = gen[BB]

// 迭代直到不动点
repeat until no change:
    for each BB:
        in[BB]  = ∪{ out[pred] | pred ∈ predecessors(BB) }
        out[BB] = gen[BB] ∪ (in[BB] - kill[BB])
```

代码实现：

```python
def _reaching_definitions(self, result: AnalysisResult):
    blocks = result.cfg_blocks
    changed = True
    while changed:      # 迭代至不动点
        changed = False
        for bb in blocks:
            new_in = set()
            for pred in bb.predecessors:
                new_in |= pred.out_set          # ∪ 所有前驱的 OUT
            new_out = bb.gen | (new_in - bb.kill)  # gen ∪ (in - kill)
            if new_in != bb.in_set or new_out != bb.out_set:
                bb.in_set  = new_in
                bb.out_set = new_out
                changed = True                  # 还有变化，继续迭代
```

### 活性分析（后向数据流）

```
// 反向传播，从 EXIT 开始
for each BB (in reverse order):
    live_out[BB] = ∪{ live_in[succ] | succ ∈ successors(BB) }
    live_in[BB]  = gen[BB] ∪ (live_out[BB] - kill[BB])
```

### 检测无效赋值（死赋值）

```python
def _detect_dead_assignments(self, result, lines):
    for bb in result.cfg_blocks:
        for i, instr in enumerate(bb.instructions):
            if instr.node_type == NodeType.ASSIGN:
                var = extract_lhs(instr)
                # 检查：该变量在后续是否还有使用
                subsequent_uses = any(
                    var in self._get_used_vars(later)
                    for later in bb.instructions[i+1:]
                )
                # 若后续无使用 且 不在 live_out 集合中 → 死赋值
                if not subsequent_uses and var not in bb.live_out:
                    result.add_issue(AnalysisIssue(
                        cwe_id="CWE-563",   # Assignment to Variable without Use
                        ...
                    ))
```

### 检测不可达代码

利用 CFG 可达性：从 ENTRY 块做 BFS，未被访问到的非空块即为死代码。

```python
def _detect_dead_code_blocks(self, result, lines):
    reachable = set()
    stack = [result.cfg_blocks[0]]   # 从 ENTRY 开始
    while stack:
        bb = stack.pop()
        if bb.id in reachable: continue
        reachable.add(bb.id)
        for succ in bb.successors:
            stack.append(succ)
    
    for bb in result.cfg_blocks:
        if bb.id not in reachable and bb.instructions:
            result.add_issue(AnalysisIssue(cwe_id="CWE-561", ...))
```

## 6. 污点分析引擎 — `analysis/taint_analyzer.py`

### Source-Propagation-Sink 模型

```
污点源 (Source)           传播规则                   污点汇 (Sink)
─────────────────         ──────────────────          ────────────────
scanf(buffer)   →  标记buffer为污点  →  system(buffer)   → CWE-78
input()         →  标记var为污点    →  cursor.execute(var)→ CWE-89
getParameter()  →  标记param为污点  →  Runtime.exec()    → CWE-78
```

实现核心：

```python
# 预设污点源（按语言分类）
TAINT_SOURCES = {
    "Python": {
        "input":       ("CWE-20", "Improper Input Validation"),
        "request.GET": ("CWE-20", "Improper Input Validation"),
        "sys.argv":    ("CWE-20", "Improper Input Validation"),
    },
    "C": {
        "scanf": ("CWE-20", "Improper Input Validation"),
        "gets":  ("CWE-120", "Buffer Copy without Checking Size"),
    },
    ...
}

# 预设污点汇（按漏洞类型分类）
TAINT_SINKS = {
    "command_injection": {
        "functions": ["system", "exec", "subprocess.run", "os.system"],
        "cwe_id": "CWE-78",
    },
    "sql_injection": {
        "functions": ["execute", "cursor.execute", "executeQuery"],
        "cwe_id": "CWE-89",
    },
}

def _detect_taint_sources(self, lines, result):
    for i, line in enumerate(lines, 1):
        for src in self.taint_sources:
            if src in line:
                m = re.match(r'\s*(\w+)\s*=', line)
                if m:
                    self.tainted_vars.add(m.group(1))  # 标记为污点变量

def _detect_taint_sinks(self, lines, result):
    for i, line in enumerate(lines, 1):
        for category, sink_info in TAINT_SINKS.items():
            for func in sink_info["functions"]:
                if func in line:
                    # 检查污点变量是否流入该 Sink
                    if any(tv in line for tv in self.tainted_vars):
                        result.add_issue(AnalysisIssue(
                            cwe_id=sink_info["cwe_id"], ...
                        ))
```

## 7. 程序切片 — `analysis/slicer.py`

### 静态后向切片算法

给定切片准则 `(line_n, var_v)`，后向切片找出所有**影响** `var_v` 在第 `n` 行取值的语句。

```python
def backward_slice(self, result, criterion_line, criterion_var):
    slice_lines = {criterion_line}
    work_vars = {criterion_var}    # 需要追踪的变量集合
    
    # 从准则行向前扫描
    for lineno in range(criterion_line - 1, 0, -1):
        line = source_lines[lineno - 1]
        defined = self._get_defined_var(line)    # 该行定义的变量
        used    = self._get_used_vars(line)       # 该行使用的变量
        
        if defined and defined in work_vars:
            slice_lines.add(lineno)
            work_vars.discard(defined)       # 该变量已找到定义点
            work_vars |= used               # 新增对 RHS 变量的追踪（数据依赖）
        
        # 控制依赖：if/while 条件影响执行路径
        if is_control_stmt(line) and any(v in line for v in work_vars):
            slice_lines.add(lineno)
            work_vars |= used
    
    return sorted(slice_lines)
```

**示例**：对于代码
```python
1: user = input()      # Source
2: cmd = user          # 数据依赖
3: cmd = cmd.strip()   # 数据依赖
4: os.system(cmd)      # Sink（准则点）
```
以 `(4, cmd)` 为准则的后向切片结果为 `{1, 2, 3, 4}`，完整追踪了污点传播路径。

### 线程安全的分析调度

分析在后台线程执行，通过 `root.after()` 回调更新 UI，避免界面卡顿：

def _run_analysis(self):
    self.progress.start(10)     # 启动进度条动画
    
    def run():
        result = engine.analyze(code)
        # 通过 after() 切回主线程更新 UI（线程安全）
